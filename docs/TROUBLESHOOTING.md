# 常见问题与调试

问题仍存在时，请先查看 [最新 Release](https://github.com/463861437/many-bricks-3ds/releases/latest) 和 [验证记录](../VALIDATION.md)，再到 [Issues](https://github.com/463861437/many-bricks-3ds/issues) 提供可复现信息。不要仅凭电脑端测试通过推断硬件问题已经解决。

## 下载、安装与启动

### 找不到 CIA

源码仓库主要保存代码和资源。打开 Release 的附件列表下载 CIA 或安装包；GitHub 自动生成的 Source code 压缩包不等于成品安装包。下载后可与该次发布的 SHA-256 校验值比较。

### FBI 安装失败

记录完整错误码，确认下载完整、SD 卡可读写且剩余空间足够，并检查设备已有可安装自制 CIA 的环境。退出正在运行的游戏或传输程序后再安装。覆盖更新无需先卸载游戏；在排查前备份 `SD:/3ds/many-bricks-3ds/`，不要用删除存档解决安装错误。

### 传完 CIA 后 HOME 没出现图标

复制文件只完成传输，需要在 FBI 中选中该 CIA 并执行 **Install CIA**。3DSX 则应放在 `SD:/3ds/many-bricks-3ds/`，从 Homebrew Launcher 启动，它不会自动出现在 HOME 菜单。

### 启动或开始游戏时出现异常页面

先核对安装的版本与 Release。1.0.1 已修复 CIA 缺少 DSP 内存映射导致的音效初始化异常，后续版本保留该配置；其他错误仍需按实际异常定位。记录发生时机、错误类型、PC/LR 等信息及所用版本。若系统生成崩溃转储，保留原文件用于后续调试；公开上传前检查其中是否含不希望公开的信息。

开发者必须使用**同次构建**的 ELF 和 map 解析地址，不能用当前重新编译的符号解释旧二进制崩溃。构建方法见 [BUILDING.md](BUILDING.md)。

## 操作与游戏

### 挡板碰到了球却没有接住

1.1.1 修复了迟接、侧面斜入和快速移动路径上的下降球漏接，电脑回归已通过，仍需真机复验。球已完全落到板身下方时不再接回，上行球也不会被板身重新接回。

若在 1.1.1 仍可复现，请记录关卡、标准/宽松模式、触屏或按键操作、是否有慢速/加长道具，以及接触的是挡板顶面、侧面还是下方；短视频有助于分清接触顺序。不要只凭单张画面判定发生了哪一步碰撞。

### 触屏或确认按钮没有立即响应

移动区域在下屏中间的触控板，底部按钮用于发球和暂停。切换场景或从 HOME/合盖恢复后，需要先松开按键/触屏，再确认下一操作；这是避免输入穿透多个画面的设计。选关只能进入已解锁的关卡。

### 小球在围墙间反复弹跳

固定墙没有生命值，也不计入剩余砖数。每个布局有入口或出口；穿透道具仍会被墙反弹。程序会在较长时间没有触砖或接球后，于下一次墙面接触时纠偏，但这不能保证所有轨迹在固定时间内返回挡板。报告卡球时请提供关卡、剩余砖数、道具和持续时间，最好附视频。

### 球太快或接球困难

在首页按 Y 或触摸模式按钮切换“宽松”，使用更宽挡板及较低球速。两种模式共用成绩和解锁。应用未提供用户自定义速度选项；如需反馈节奏，请说明设备型号、关卡及当时球数。

### 没有声音

先确认设备音量、首页音效开关；程序音效初始化失败时会提示并继续无声运行。DSP 可用性取决于启动环境，发行包不含 DSP 固件。电脑音频单元测试只验证调用与资源管理，不保证硬件输出；反馈时说明 CIA/3DSX 启动方式和系统环境。

## 保存与升级

### “进度未能保存”或重启后进度消失

检查 SD 卡是否可写、空间是否足够，以及 `SD:/3ds/many-bricks-3ds/` 是否是目录。游戏使用 `progress0.bin` 和 `progress1.bin` 双槽；不要在运行中移动或替换它们。两份都无效时不能自动重建已经丢失的成绩。

保存发生在暂停、丢球、关卡结束或正常退出等时刻，不保存局内球和砖墙状态。想保留新成绩时使用正常退出，避免直接断电。双槽机制降低风险，无法保证任意断电下数据完整。

### 旧版第 36 关通关后没有直接开放第 37 关

旧存档只记录“已解锁到第几关”，没有单独记录最终关是否已完成。读取旧版解锁 36 的记录时会保留为 36，再通过一次第 36 关即可解锁 37；其他旧成绩和设置继续保留。

### 如何备份、恢复或重新开始

退出游戏后复制整个 `SD:/3ds/many-bricks-3ds/`。恢复时同时替换 `progress0.bin` 和 `progress1.bin`，否则另一份更新的记录可能被优先加载。

若要从头开始，先备份，再将两份 `.bin` 存档移出原目录；不要删除同目录中的 3DSX/SMDH 启动文件。新增进度会建立新存档。新版存档不保证能在旧版本中读取。

## 开发环境

| 提示或现象 | 检查方法 |
|---|---|
| 缺少 devkitARM 或 libctru | 安装 `3ds-dev`，检查 `DEVKITPRO`、`DEVKITARM` 与工具链文件；路径不要指向普通桌面编译器 |
| makerom/bannertool/ctrtool 找不到 | 添加到 `PATH`，或设置 `MAKEROM`、`BANNERTOOL`、`CTRTOOL` 到实际可执行文件 |
| makerom 0.19.0 被拒绝 | 使用已验证 0.18.4；0.19.0 有上游版本编码缺陷 |
| Python 缺少 PIL | 在用于预览/字库的 Python 环境安装 Pillow |
| 测试无法使用 sanitizer | 检查本机 Clang/GCC 与 sanitizer 运行时，测试需在电脑执行，不能用 ARM 交叉编译器 |
| CIA 校验和 ELF 不匹配 | 清理后重新构建，确保 CIA、ELF、图标和配置来自同一次构建 |
| 自制 CIA 的签名检查失败 | Ticket/TMD/AccessDescriptor 没有官方签名属预期；内容或 ExeFS 哈希失败仍需排查 |
| 新增中文显示缺字 | 用 Noto Sans SC 重新生成 `include/font_data.hpp`，再构建并检查预览 |

完整命令见 [BUILDING.md](BUILDING.md)。提交构建问题时保留第一处错误和必要上下文，不要只贴最后一行 `make` 失败。

## 报告问题需要的信息

- 版本号和下载来源；自行编译时附 commit、工具链版本及是否有修改。
- 设备型号、系统/自制软件环境、CIA 或 3DSX 启动方式。
- 从启动到触发问题的最短步骤、发生频率、预期与实际行为。
- 关卡、模式、输入方式、道具状态；相关截图、短视频或脱敏日志。
- 存档或崩溃问题可先说明是否保留相关文件，按维护者需要提供。
