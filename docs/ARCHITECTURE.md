# 源码结构与扩展指南

游戏使用 C++17 和 libctru，将纯游戏逻辑、绘图、输入转换、存档及 3DS 平台生命周期分开。电脑端测试复用正式游戏代码；硬件服务由测试替身提供。

## 目录与职责

| 路径 | 职责 |
|---|---|
| `source/main.cpp` | 3DS gfx/HID/APT 初始化、固定时间步主循环、HOME/合盖暂停、声音及存档提交 |
| `source/game.cpp`、`include/game.hpp` | 状态、关卡生成、连续碰撞、道具、连击及计分 |
| `source/controls.cpp`、`include/controls.hpp` | 统一触屏/按键输入到菜单动作和挡板目标位置 |
| `source/render.cpp`、`include/render.hpp` | CPU 绘图，上屏 400×240、下屏 320×240 |
| `source/audio.cpp`、`include/audio.hpp` | 合成音效、NDSP 队列和资源释放 |
| `source/save.cpp`、`include/save.hpp` | 双槽存档、校验、旧格式迁移 |
| `include/font_data.hpp` | 由 Noto Sans SC 预生成的字形数据 |
| `tests/` | 正式逻辑、渲染、存档/输入、挡板、音频和主循环回归测试；预览程序 |
| `packaging/` | CIA 配置、图标/横幅、生成及验证脚本、第三方许可 |
| `docs/` | 开发、安装问题与架构文档 |

## 状态与时间步

`Scene` 定义首页、选关、准备发球、游玩、暂停、单关完成、失败和全部完成。`Controller` 接收 `Input`，更新场景及挡板目标；`Game::step()` 只在准备或游玩状态推进。`View` 保存页面、触屏和提示状态，`render()` 读取它们而不修改游戏状态。

主循环使用 1/120 秒固定逻辑步长，单帧经过时间最多累计 50ms；`Game::step()` 再划分为不超过 1/240 秒的碰撞子步。HOME/合盖事件会暂停并清空时间累积。切换画面后需要释放确认按键或触屏，避免一次输入连跳多个页面。

球、砖、墙、道具及粒子使用固定容量数组：256 球、128×26 砖格、最多 8 段墙、32 个道具、192 个粒子。当前关卡实际使用 2–6 段墙。提高容量会增加内存和绘制/碰撞成本，应重新测量真机表现。

## 碰撞与接球

球沿每个子步的位移对扩张后的矩形做连续扫掠；只查询路径附近的砖格，寻找最早接触点，消费剩余时间后继续反弹。每子步有碰撞次数上限，避免异常几何导致无限循环。

1.1.1 将挡板接触从单一顶面检测改为完整板身检测，并使用球相对移动挡板的位移。因此下降球迟接、侧面斜入及挡板快速移动路径都可被检测。反弹角依据接触瞬间的板中心计算；接住后将球置于板面上方，避免重复接触。上行球不重新接回，已完全位于板下方的球继续丢失。

围墙和场地边界始终反弹。穿透道具只穿过可破坏砖块。持续未碰砖或挡板的球在后续墙面接触时调整方向，帮助离开周期轨迹；不会瞬移或直接增加分数。碰撞回归集中在 `tests/test_game.cpp` 与 `tests/test_paddle.cpp`。

## 关卡生成

关卡由 `Game::startLevel()` 确定性生成，不依赖外部地图文件：

1. 使用关卡序号初始化本关随机数种子、机会、道具和计分。
2. `buildWalls()` 按章节和变体创建固定墙。
3. `filled()` 决定每个砖格是否存在；`clearOfWalls()` 移除与围墙或预留间隙冲突的砖。
4. 设置颜色、单击/双击耐久并统计实际砖数，准备首球。

布局按 9 章×12 变体组织，`NAMES` 保存 108 个中文名称。可见砖面为 2×2 像素，砖格间距为 3×3。墙、球和砖的几何与绘制位置必须一致。

### 调整现有关卡

1. 在 `source/game.cpp` 修改 `filled()`、`buildWalls()` 或该关名称。保持砖墙位于上半屏，避免堵死回廊入口。
2. 按**球半径**检查开口宽度，而不是只看屏幕上是否存在空白；围墙不能完全围住可破坏砖块。
3. 保留最下方墙体到挡板的接球空间。若更改尺寸或球速，同时更新对应边界和反应距离测试。
4. 在 `tests/test_game.cpp` 增加能复现新布局风险的案例，例如窄入口、墙角恢复、低砖回球及清场计数。
5. 更新中文名字后重生成字库，运行 `./check.sh` 和预览，目视检查真实像素布局。
6. 编译 CIA 并校验后，真机检查触屏、接球余量、密集多球和最终少量砖的清场体验。

### 增加关卡数量

不能只改 `LEVEL_COUNT`。`source/save.cpp` 对当前 108 关格式有静态断言，因为存档记录长度包含每关分数。

需要一并更新：关卡生成范围、`NAMES`、选关分页/三位数字显示和测试；定义新存档魔数、固定长度、字段边界及从 36/108 关旧格式迁移的规则，保留旧成绩和解锁。增加损坏文件、混合版本双槽、序列回绕和新增关成绩归零的回归。不要把旧格式按新长度直接解析，也不要为了编译通过删除格式断言。

## 存档与渲染

当前 `MB3DS002` 格式为 460 字节，旧 `MB3DS001` 为 172 字节。内容包括递增序列、解锁、最高分、设置和逐关成绩；结尾校验值用于发现损坏，并非加密或防篡改机制。读取时先完成验证再应用资料，两个有效槽按序列选择较新者。保存先写临时文件，再替换另一槽，保留上一份记录；不能保证任意断电条件下不丢档。

渲染直接写 libctru 的 BGR8 帧缓冲，按列存储、从下到上排列。上屏使用 2D，未实现立体 3D。绘制有边界裁剪，球位于围墙前方以提高辨认度。新增画面必须同时检查双屏的真实尺寸；桌面放大预览不能替代真机可读性。

## 平台与发布配置

`packaging/app.rsf` 控制 CIA 服务访问、Title ID 和内存映射。NDSP 需要的两段 DSP 映射是已修复启动崩溃的重要配置，`packaging/verify-cia.py` 会检查，不应为了精简配置移除。

修改发行版本时同步 `build-cia.sh` 的版本编码、`packaging/app.rsf` 的 `RemasterVersion`、`packaging/verify-cia.py` 的预期值、`packaging/package-release.py` 的版本检查及文档，然后重建并验证。发布二进制时保留对应 ELF/map 与准确源码 tag。详见 [构建与打包](BUILDING.md) 及 [贡献说明](../CONTRIBUTING.md)。
